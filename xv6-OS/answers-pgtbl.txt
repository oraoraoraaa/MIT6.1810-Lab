Answer:

va low to high (0x0 - 0x9000)

1. 0x0 and 0x1000

- Logical Meaning: Text section, storing actual instructions and strings.
- Permission: 0x5B - 00 0101 1011 (VR-XU)

2. 0x2000

- Logical Meaning: Data section, storing initialized global/static variables.
- Permission: 0x17 - 00 0001 0111 (VRW-U)

3. 0x3000

- Logical Meaning: Guard page that user program cannot access. Prevent user stack overflow.
- Permission: 0x7 - 00 0000 0111 (VRW--)

4. 0x4000

- Logical Meaning: User stack (1 page size).
- Permission: 0xD7 - 00 1101 0111 (VRW-U)

5. 0x5000 - 0x9000

- Logical Meaning: Heap (unmapped memory, doesn't exist for now)
- Permission: 0

va high to low (0x3FFFFFF000 - 0x3FFFFF6000)

1. 0x3FFFFFF000

- Logical Meaning: Trampoline (1 page size)
- Permission: 0x4B - 00 0100 1011 (VR-X-)

2. 0x3FFFFFE000

- Logical Meaning: Trapframe (1 page size)
- Permission: 0xC7 - 00 1100 0111 (VRW--)

3. 0x3FFFFFD000 - 0x3FFFFF6000

- Logical Meaning: Unused (unmapped memory, doesn't exist for now)
- Permission: 0

Speed up system calls

uptime(): The number of timer ticks since boot could be stored in the shared page and updated by the timer interrupt handler. User programs could read it without a system call.

getppid(): Parent process ID rarely changes, so it could be stored in the shared page.

gettimeofday() (if implemented): Current time could be updated periodically in the shared page.

getcpu() (if implemented): Which CPU core the process is running on could be stored and updated on context switches.
